# 项目立项文档：迹录 (TraceLife)

---

## 1. 项目立项说明

**项目名称**：迹录（英文名：TraceLife）

**立项背景**：
- 开发者从零学习 Flutter 移动端开发，需要一个有实际用途的项目作为练习
- 日常生活中有记录需求（日记、纪念日、打卡等），但现有 App「每一迹」需要付费会员
- 已有开源参考项目 Omnix（Flutter + SQFlite）可作为技术参考

**项目性质**：个人练手项目，第一版仅自己使用

**开发周期目标**：V1 在 1-2 周内完成，可编译 APK 安装到安卓手机

---

## 2. 核心定义和受众

**一句话定义**：
> 一个以时间轴为核心的个人生活轨迹记录工具。

**目标受众**：
- **第一版**：开发者本人
- **后续**：可以分享给身边有同样需求的朋友（非商业目的）

**用户画像**：
- 年龄：20-30 岁
- 身份：学生 / 刚工作的年轻人
- 习惯：想要记录生活但不想用臃肿的 App，对数据隐私敏感
- 需求层次：先满足日记 + 纪念日记录，逐步扩展到习惯 / 计划 / 记账

---

## 3. 解决痛点问题

| 痛点 | 解决方案 |
|------|---------|
| 每一迹好功能需要付费会员，不想花钱 | 完全免费，自己掌控 |
| 大而全的 App 功能太多，只想用其中几个 | 按需迭代，每版只加 1-2 个功能 |
| 数据在别人服务器上，不放心 | 纯本地存储，无需联网 |
| 很多记录 App 打开慢、广告多 | 极简纯本地，秒开无广告 |
| 想学 Flutter 开发但缺一个完整项目 | 从零到一，完整走一遍开发流程 |

---

## 4. 核心价值主张

```
一日一记，生活有迹可循
Trace your life, every day matters.
```

**三个关键词**：
- **极简** — 每个版本只做最必要的功能
- **本地优先** — SQLite 本地存储，数据 100% 在你手里
- **日期驱动** — 所有内容围绕「某一天发生了什么」

---

## 5. 第一版核心目标

**一句话目标**：
> 2 周内做出一个能装到安卓手机上、可以写日记 + 记录纪念日的 App。

**量化目标**：
- ✅ 日记：能写 / 编辑 / 查看 / 删除日记
- ✅ 正数日：能添加 / 查看「XX 事件已过 N 天」的卡片
- ✅ Today 聚合页：打开 App 就看到今天的日记入口 + 正数日列表
- ✅ 纯本地运行，无需联网
- ✅ 能在 Android 真机上安装使用

## 6. 业务边界

### 做（V1 范围）
| 模块 | 包含 |
|------|------|
| 日记 | 纯文本写入、按日期查看、编辑、删除 |
| 正数日 | 标题 + 目标日期 + emoji + 自动计算已过天数 |
| Today 首页 | 当天日期显示 + 日记快捷入口 + 正数日卡片展示 |

### 不做（V1 明确排除）
- ❌ 用户登录 / 注册系统
- ❌ 云端同步 / 多设备
- ❌ 社交分享 / 公开
- ❌ AI 分析 / 智能建议
- ❌ 富文本编辑器 / 图片附件
- ❌ 多主题 / 个性化
- ❌ iOS 版本（Flutter 可编译但不保证在 iPhone 上完美运行）
- ❌ 数据导出 / 备份
- ❌ 密码锁 / 隐私保护

### 未来边界（留好接口但不实现）
- 云端同步模块（留 SyncService 抽象）
- 多用户隔离（留 UserContext 但不用）
- 通知提醒（留 NotificationService 抽象但不调原生 API）

## 7. 产品流程和用户路径

### 7.1 整体导航结构

```
底部导航栏（3个Tab）:
┌──────────┬──────────┬──────────┐
│  Today   │  日记    │ 正数日    │
│  (首页)   │          │          │
└──────────┴──────────┴──────────┘
```

### 7.2 核心用户路径

**路径 A：写日记（每日核心操作）**
```
打开 App → Today 首页（看到今天日期）
         → 点击「写日记」→ 进入日记编辑页
         → 写内容 → 保存 → 回到首页（看到今日摘要）
```

**路径 B：查看历史日记**
```
底部 Tab 日记 → 看到日历（有日记的日期高亮）
             → 点击某天 → 阅读/编辑日记
```

**路径 C：添加正数日**
```
底部 Tab 正数日 → 列表展示已有正数日
               → 点 "+" → 输入标题 + 选择日期 + 选 emoji
               → 保存 → 首页和正数日列表同步更新
```

**路径 D：查看已过天数（高频查看）**
```
打开 App → Today 首页 → 直接看到所有正数日的卡片
         → 每张卡片显示「已过 N 天」
```

### 7.3 页面流转图

```
SplashScreen (1秒)
    │
    ▼
TodayPage (首页 / 默认Tab)

    ├── 下部：今日日记入口（有则显示摘要，无则"记录今天"）
    │
    ├── Tab 2: DiaryPage
    │     ├── 日历视图
```

## 8. 核心业务对象

### 8.1 Diary（日记）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int (PK, 自增) | 主键 |
| date | TEXT (UNIQUE) | 日期，格式 yyyy-MM-dd，唯一索引 |
| content | TEXT | 日记正文 |
| mood | INTEGER (1-5) | 心情指数，默认 3 |
| created_at | TEXT | 创建时间 ISO8601 |
| updated_at | TEXT | 最后修改时间 ISO8601 |

**约束**：每天最多一条日记（date 唯一）

### 8.2 DayCounter（正数日）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int (PK, 自增) | 主键 |
| title | TEXT | 事件标题，如"认识你" |
| target_date | TEXT | 目标日期 yyyy-MM-dd |
| emoji | TEXT | 表情符号，默认 "📅" |
| color_index | INTEGER | 卡片颜色，默认 0 |
| sort_order | INTEGER | 排序权重 |
| created_at | TEXT | 创建时间 |

**计算字段（不存数据库，运行时计算）**：
- `days_passed = today - target_date`（已过天数）
- `is_future = target_date > today`（用于标识未来日期 / 倒计时）

### 8.3 数据库 ER 关系（V1）

```
┌─────────────────┐      ┌─────────────────────┐
│    Diary         │      │    DayCounter        │
├─────────────────┤      ├─────────────────────┤
│ id (PK)         │      │ id (PK)             │
│ date (UNIQUE)   │      │ title               │
│ content         │      │ target_date         │
│ mood            │      │ emoji               │
│ created_at      │      │ color_index         │
│ updated_at      │      │ sort_order          │
└─────────────────┘      │ created_at          │
                         └─────────────────────┘
```

V1 **两张表独立，没有外键关联**。后续版本的表也保持独立，通过 date 字段和通用查询接口关联。

## 9. 技术路线

### 9.1 技术选型

| 层级 | 选型 | 理由 |
|------|------|------|
| 框架 | **Flutter** | 跨平台、Windows 可开发、热重载学习效率高 |
| 语言 | **Dart** | Flutter 官方语言，语法现代对新手友好 |
| 本地存储 | **SQFlite** | 成熟轻量、参考项目 Omnix 已验证、CRUD 代码极简 |
| 状态管理 | **setState + InheritedWidget**（V1） | 项目小不需要引入复杂状态管理库，降低学习曲线 |
| 日历组件 | **table_calendar** | Flutter 生态最成熟的日历库 |
| 图表（V1 不需要） | fl_chart | 后续版本做统计时引入 |
| 主题 | **Material Design 3** | Flutter 内置，自动暗色模式 |

### 9.2 为什么不用 X？

| 方案 | 为什么不选 |
|------|-----------|
| React Native / Expo | 需要 JS/TS 基础，Android 上 Flutter 渲染性能更好 |
| Kotlin 原生 | 仅 Android，以后想加 iOS 得重写 |
| Isar / Hive | V1 功能简单 SQFlite 够用，Isar 学习曲线略高 |
| Provider / Riverpod / Bloc | V1 只有 2 个功能模块，setState 完全够用，以后再引入 |
| Firebase | V1 纯本地不需要后端 |

### 9.3 关键依赖（V1）

```yaml
  flutter: sdk:flutter
  sqflite: ^2.4.2
  path_provider: ^2.1.5
```

### 12.2 架构原则

1. **Feature 隔离**：每个功能在自己的文件夹里，不跨功能引用。新功能 = 新建文件夹 + 在 core/database 加一张表 + 加到底部导航
2. **Core 跨功能共享**：数据库、主题、工具函数放 core，所有功能共同依赖
3. **单向数据流**：用户操作 → Model 更新 → 数据库写入 → UI 重新渲染
4. **V1 不用状态管理库**：Widget 内部维护状态（setState），页面间传参，数据通过 DatabaseHelper 单例读写
5. **命名规范**：
   - 文件：`snake_case.dart`
   - 类：`PascalCase`
   - 变量/函数：`camelCase`
   - 常量：`SCREAMING_SNAKE_CASE`

### 12.3 数据库设计关键决策

- **日期存储格式**：统一用 `yyyy-MM-dd` 字符串，不用时间戳。原因：可读、可直接用于 SQL WHERE 比较、避免时区问题
- **mood 用整数**：1-5，不用字符串。原因：排序/统计方便，前端映射为表情展示
- **不设外键**：V1 表间无关联，后续版本添加关联时用逻辑关联（通过 date 字段 join），不用数据库外键约束。原因：简化迁移、SQLite 外键需要额外配置

## 13. 项目爆点和差异点

### 和「每一迹」的对比

| 维度 | 每一迹 | 迹录 (TraceLife) |
|------|--------|-----------------|
| 价格 | 会员制付费 | **完全免费** |
| 联网 | 需要联网 | **纯本地，无需联网** |
| 数据所有权 | 在云端 | **在你的手机里** |
| 功能量 | 大而全，很多用不到 | **按需迭代，每版精炼** |
| 加载速度 | 有网络等待 | **秒开** |
| 广告 | 有 | **无** |
| 自定义 | 固定功能 | **自己写，想加什么加什么** |

### 差异点总结

1. **本地优先**：不依赖任何云端服务，数据 100% 在本地
2. **极简迭代**：不是大而全，每个版本聚焦 1-2 个功能
3. **自己掌控**：自己写的代码，想加什么功能随时加
