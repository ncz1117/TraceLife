### Phase 2: 午夜翻页（0.5 天）

**目标**：纪念日 / Today 页的大数字在午夜 00:00:00 真正"翻页"——替代当前的静态 + 心跳。

**命令**：`$midnight`

#### 设计思路

```
现状：1.8s 心跳脉动（V3）
新方案：数字 + 状态在跨日时直接"翻"
        24 小时里没有脉动（避免视觉疲劳）
        翻的时候有 200ms "翻牌"动画（不是心跳，是"翻"）
```

#### 核心机制

```dart
// MidnightWatcher（全局单例）
class MidnightWatcher {
  Timer? _timer;
  DateTime _knownDate = DateTime.now();

  void start(VoidCallback onMidnight) {
    _timer = Timer.periodic(Duration(seconds: 30), (_) {
      final now = DateTime.now();
      if (now.day != _knownDate.day ||
          now.month != _knownDate.month ||
          now.year != _knownDate.year) {
        _knownDate = now;
        onMidnight();  // 触发所有订阅者
      }
    });
  }
}

// 提供者
final midnightSignalProvider = StateProvider<int>((ref) => 0);
// 数字变化触发方式：
final counterAsync = ref.watch(dayCounterProvider(...).future);
ref.listen(midnightSignalProvider, (_, __) {
  ref.invalidate(dayCounterProvider);
});
```

#### 翻牌动效

| 元素 | 动画 |
|------|------|
| 旧数字淡出 + 向上滑 | 200ms easeOut |
| 短暂黑屏 | 50ms（让眼睛"刷新"）|
| 新数字淡入 + 向下滑 | 200ms easeIn |

总时长 ~450ms，**只发生在午夜**一次，不会重复。

#### 后台策略

- App 切后台：依赖 `didChangeAppLifecycleState(resumed)` 时检查日期差
- App 切前台：同上 + 强制刷新一次
- **不依赖**系统的精确闹钟（耗电 + 不可靠）

#### 短期"今日更新"反馈

- 翻页后顶部短暂出现 "✨ 新的一天" badge
- 1.5s 后自动消失（渐出 200ms）

## 🎁 选做 Phase 6: 打卡模块（1-1.5 天）

**目标**：补 1 个原规划模块，最契合品牌的是 **打卡**。

**命令**：`$checkin`

### 数据模型

```dart
@freezed
class CheckIn with _$CheckIn {
  factory CheckIn({
    required int id,
    required String name,         // 习惯名
    required String emoji,        // 图标
    String? description,         // 描述
    @Default(1) int targetPerDay, // 每日目标次数
    @Default(0) int currentStreak,  // 连续天数
    @Default(0) int longestStreak,  // 历史最长
    DateTime? lastCheckAt,       // 上次打卡时间
    @Default(true) bool active,  // 是否启用
    required DateTime createdAt,
  }) = _CheckIn;
}

class CheckInRecord {
  final int id;
  final int checkInId;
  final DateTime checkedAt;      // 某次打卡的时间
  final String? note;            // 打卡附注
}
```

### 表设计（v7 迁移）

```sql
CREATE TABLE check_ins (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  emoji TEXT NOT NULL,
  description TEXT,
  target_per_day INTEGER DEFAULT 1,
  current_streak INTEGER DEFAULT 0,
  longest_streak INTEGER DEFAULT 0,
  last_check_at TEXT,
  active INTEGER DEFAULT 1,
  created_at TEXT NOT NULL
);

CREATE TABLE check_in_records (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  check_in_id INTEGER NOT NULL,
  checked_at TEXT NOT NULL,
  note TEXT,
  FOREIGN KEY (check_in_id) REFERENCES check_ins(id) ON DELETE CASCADE
);

CREATE INDEX idx_check_in_records_check_in_id ON check_in_records(check_in_id);
CREATE INDEX idx_check_in_records_checked_at ON check_in_records(checked_at);
```

## 🚧 风险与决策点

### 决策点 1：要不要做打卡？

| 选项 | 评估 |
|------|------|
| **做打卡** | 契合品牌 + 1.5 天可完成 + 1 个新模块让 V4 有"成长"感 |
| **不做** | 1.75 天收尾 V3，V5 再做新功能 |
| **做其他** | 计划/资产/订阅 都不如打卡契合 |

**建议**：做打卡。V3 重设计令后正好需要 1 个"新模块"来验证 token 体系的扩展性。

### 决策点 2：午夜翻页替代心跳 vs 两者并存？

| 选项 | 评估 |
|------|------|
| **替代** | 午夜翻页 1 天 1 次（克制），心跳 1.8s 一次（持续）。两者并存 = 视觉冲突 |
| **并存** | 心跳只在 ViewPage 详情页（持续进入），翻页在所有页（跨日一次）|
| **只翻页** | ViewPage 也用翻页，没有脉动 |

**建议**：替代。V3 心跳验证过"心动但没什么用"，翻页 1 天 1 次 = 真正的"生命时刻"。

### 决策点 3：bughunt 发现的 P2 问题放哪？

| 选项 | 评估 |
|------|------|
| **当场修** | V4 工期 +0.5~1 天 |
| **放进 V4.1 hotfix** | 单独发版本，1 周内 |
| **随 V5 一起修** | 拖延太久 |

**建议**：当场修 P1，当场修会让 V4 拖到 2.5 天。**P2 进 V4.1 hotfix**。
